# UI/UX 設計

先讀取以下文件，確認功能、角色與已定案的決策，再開始設計：

- `docs/product/features.md`：功能規則的唯一來源；〈角色權限〉決定每個角色能看到、能做什麼
- `docs/product/overview.md`：用戶畫像與年齡分層（幼兒、童年、青少年）
- `docs/product/roadmap.md`：第一版範圍；第二版的功能不畫
- `docs/tech-decisions.md`：D-01 Flutter、D-11 主題、D-13～D-15 多語系
- `docs/data-model-qa.md`（若存在）：已定案的業務規則，畫面要照著呈現
- `docs/design-qa.md`（若存在）：之前提出、已回答或待回答的問題

`SPEC.md` 是歷史初稿，與上述文件不一致時以上述文件為準。

## 範圍

這一階段只做**低保真**：畫面有哪些、各自顯示什麼資料、按了會去哪裡。

- 主題（4 個）與 Logo 已在設計稿定案：<https://claude.ai/artifact/XkWynXKhLPrwvBhwCYXcC4>。線框沿用其資訊層級，配色、字型、動畫細節留到開發時調整。
- 業務規則（金額怎麼算、狀態怎麼轉換）以 `data-model-qa.md` 與 `features.md` 為準；畫面發現規則有缺口時提問，不自行補規則。

## 設計原則

1. **一台手機、全家共用**：父母模式與孩子模式的切換是整個導覽的骨架；進入父母模式、驗證任務等操作要標出 PIN 驗證點。
2. **孩子畫面只有一套**：幼兒、童年、青少年共用同一套孩子畫面（`docs/design-qa.md` UQ-04），不另做年齡版本。
3. **離線與沒登入是常態**：每個需要 Google 的入口都要畫出沒登入時的樣子（例如「目前沒有備份」提醒）。
4. **每個畫面列出要顯示的資料**：這份清單是 `/data-model` 設計 Schema 的輸入，要具體到欄位層級（例如「收入來源：長輩名稱」「這筆紀錄已作廢：劃線顯示」）。
5. **空狀態與錯誤狀態**：第一次使用、沒有目標、沒有任務、可出金額為 0 時，畫面各顯示什麼。
6. **文字長度考慮多語系**：英文通常比中文長，按鈕與標籤不要依賴中文字數排版（D-13）。

## 問題怎麼提

規格沒講清楚、會影響畫面或流程的地方，**不在對話裡逐題提問**，而是寫進 `docs/design-qa.md`，格式照 `docs/product/discover-qa.md`：

- 分「已確認」與「待確認」兩區，題號 `UQ-01`、`UQ-02`…，往後接、不重用
- 一題只問一件事，附編號選項與建議（含理由）；需要比較版面時附 ASCII 草圖
- 對話只回報：新增了哪幾題、建議先回答哪一題
- 用戶說「已回答」時：重新讀取 `docs/design-qa.md`，把有明確答案的題目移到「已確認」並落實到設計；回答有疑慮或引出新問題時，重新查證後留在或新增到「待確認」，不要自行拍板
- 若答案改變了產品規則，同步更新 `docs/product/features.md`

## 執行步驟

### 第一步：畫面清單
從 `features.md` 逐節列出第一版需要的所有畫面，依「共用／父母模式／孩子模式／設定」分組。每個畫面一行說明用途。完成標準：`features.md` 每一節的功能都至少對應到一個畫面。

完成後把有疑義的地方寫進 `docs/design-qa.md`，等用戶回答後再往下做。

### 第二步：導覽結構
用 Mermaid 畫出畫面之間怎麼跳轉：首頁、Tab 或選單、父母／孩子模式切換、PIN 驗證點、第一次開 App 的引導流程。

### 第三步：主要流程
每條流程用 Mermaid 畫出步驟與分支，至少涵蓋：

- 第一次開 App：建立第一位父母與 PIN、新增孩子
- 記一筆收入（含長輩給錢、附一句話、指定給目標）
- 出金（含可出金額不足、需先把目標退回解鎖的情境）
- 任務：建立 → 孩子回報 → 父母驗證或退回 → 獎勵入帳
- 儲蓄目標：建立 → 瀑布填充進度 → 可達成 → 孩子確認（已達成、鎖錢）→ 目標出金 → 已完成
- 更正記錯的帳
- 開啟雲端備份、匯出／匯入（只畫入口與畫面，細節流程由 `/auth-design` 設計）

### 第四步：低保真線框
每個畫面一張 ASCII 線框，附上：

- 要顯示的資料（欄位層級）
- 可以做的操作，以及操作後去哪個畫面
- 空狀態、錯誤狀態

## 完成後

將設計寫入 `docs/design.md`，包含：

- 畫面清單（分組）
- 導覽結構圖（Mermaid）
- 主要流程圖（Mermaid）
- 每個畫面的線框、顯示資料、操作、狀態
- 「交給下一階段」：列出 `/data-model` 需要支援的查詢與欄位、`/auth-design` 需要處理的 PIN 驗證點與 Google 入口

「待確認」清空、設計寫入 `docs/design.md` 後，`docs/design-qa.md` 可以刪除（先問用戶）。
