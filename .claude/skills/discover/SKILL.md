# 產品探索

以專業產品經理的角色，從 SPEC.md 了解初始想法，透過**問答文件**逐步釐清需求，最終整理成完整的產品規格文件體系。

## 執行步驟

1. 讀取 `SPEC.md`（只是初稿，不受其結構限制）、`docs/product/` 既有文件，以及 `docs/product/discover-qa.md`（若存在）
2. 對照「提問主題」，找出還沒問、或回答之間有衝突的地方
3. 把新題目寫進 `discover-qa.md` 的「待確認」，**不在對話裡逐題提問**
4. 對話只回報：新增了哪幾題、建議先回答哪一題（以及原因），然後等用戶在文件裡作答
5. 用戶說「已回答」時，依照下方「回收回答」處理
6. 提問主題都已釐清、「待確認」清空後，才整理正式的產品規格（見「產品規格文件結構」）

## 問答文件 `docs/product/discover-qa.md`

分成兩區：

- **已確認**：依主題整理成條列的定案結論，不保留「Q 幾」的原始問答形式
- **待確認**：只放尚未定案的題目，編號 `WD-01`、`WD-02`…

每一題的格式：

```md
#### WD-xx 題目（一句話）

背景：為什麼要問、和哪個已確認的結論有關（沒有就省略）

1. 選項
2. 選項
3. 選項

- 建議：**x**。理由一句話。

回答：
```

出題規則：

- **一題只問一件事**。不要把 (A)(B)(C) 好幾個子題塞進同一題，用戶通常只會回第一個
- 每題都要附編號選項，盡量列出常見答案，讓用戶可以回「1 3」或「同意」
- **每題都要附建議**：用戶不一定有答案，有建議才好下判斷
- 選項之間互斥時，要寫清楚是單選；可以複選時才說可複選
- 依主題分組（目標、收入與出金、任務、協作與同步…），會影響技術選型的題目加上 ⚠ 標記

## 回收回答

用戶說「已回答」時：

1. 重新讀取 `discover-qa.md`，不要用記憶中的版本
2. 已有明確答案的題目：把結論寫進「已確認」對應的主題，再從「待確認」刪掉這一題
3. 回答與既有結論或 `SPEC.md` 衝突時：在「已確認」用 ⚠ 標註差異，並說明以哪一個為準
4. 回答裡表示有疑慮、或答案本身又引出新的矛盾：重新查證既有文件，修改選項與建議後**留在「待確認」**，不要自行拍板
5. 回答衍生出新問題時：新增 WD 題目，編號往後接，不重用舊編號
6. 對話只回報：哪些題已定案、哪些題留下或新增，以及原因

## 提問主題（依序展開，不跳躍；同一批 WD 可以涵蓋好幾個主題）

### 一、用戶與痛點
- 現有解決方案和痛點（現金、記帳本、LINE、現有 app）
- 主要使用者技術程度
- 使用頻率和觸發情境

### 二、角色與生命週期
- 不同年齡階段的使用方式差異
- 各角色的核心任務和操作
- 孩子成年後的延伸場景

### 三、核心功能邊界
- 每個功能的詳細機制（零用錢、任務、目標）
- 出金流程
- 多人協作與同步需求

### 四、差異化與競品
- 競品體驗和不滿之處
- 家族共用的獨特價值主張

## 產品規格文件結構

根據收集到的需求量，彈性決定文件組織方式：

**需求較少時** — 單一文件即可：
```
docs/product/spec.md
```

**需求中等時** — 按主題分檔：
```
docs/product/
├── overview.md       # 願景、用戶畫像、問題定義
├── features.md       # 功能清單與優先級
└── roadmap.md        # MVP 範圍與階段規劃
```

**需求複雜時** — 完整資料夾體系：
```
docs/product/
├── overview/
│   ├── vision.md         # 產品願景與目標
│   ├── personas.md       # 用戶畫像（父母、長輩、孩子各年齡段）
│   └── problem.md        # 問題定義與現有痛點
├── features/
│   ├── allowance.md      # 零用錢機制
│   ├── tasks.md          # 任務與獎勵系統
│   ├── goals.md          # 儲蓄目標
│   ├── payout.md         # 出金機制
│   └── collaboration.md  # 多人協作
└── roadmap.md            # MVP 定義與版本規劃
```

## 完成後

- 前提：`discover-qa.md` 的「待確認」已清空
- 判斷需求複雜度，選擇對應的文件結構
- 將所有發現整理寫入 `docs/product/` 下的對應檔案
- SPEC.md 可保留作為歷史初稿，或在頂部加上指向新文件的說明
